# Lint カバレッジマップ（採否台帳）

本書はプロダクトの**決定的チェック（Lint / 静的解析）の採否台帳**である。カタログ（`documents/development/static-check-standard.md`）の25カテゴリすべてについて「どの手段で担保するか / なぜ採用しないか」を記録し、**カテゴリを採用しないことでチェックが黙って消えることを防ぐ**。不採用カテゴリは「AI レビュー担保」に割り当ててレビューガイド側に観点として残し、担保の所在を常にこの台帳から辿れるようにする。作成・更新は `lint-scaffolding` スキルが行い、`quality-check` の体制レビュー（統合レビュアー・QA・専門家）は本台帳で Lint 担保に割当済みの項目をレビュー対象外とする。

## カバレッジマップ

固定列（番号 / カテゴリ / 採用基準 / 🤖）はカタログ §2 からの転記であり、書き換えない。記入するのは右3列である。

- **担保手段**: 配線した具体の資産・ツール参照（例: `lint/eslint/harness.config.mjs` の correctness グループ、`lint/ast-grep/security/`、`.ai-dev-helm-lint.json` の secrets チェック）。AI レビュー担保の場合は対応するレビューガイドの節を書く
- **採用状況**: `採用` / `部分担保（Lint + AI レビュー）` / `不採用` / `AI レビュー担保` のいずれか。機械チェック可能なのに Lint を配線しない選択は `不採用` ではなく `AI レビュー担保` とする。`不採用` は該当技術がない等、チェック対象自体が存在しない場合に限る。**`部分担保（Lint + AI レビュー）`** は、配線した Lint 資産がそのカテゴリのカタログ「チェック内容の例」の一部しかカバーしない場合に用いる（例: B2 の security ast-grep が eval / 弱いハッシュ / TLS 検証無効化 / シェルコマンドインジェクションのみを担保し、SQL/XSS 等は残る）。この場合、**担保手段**列に Lint がカバーするスライスを記録し、**理由・参照**列に AI レビューへ残す残差（未担保範囲）を記録する。部分担保カテゴリはレビューガイドの「Lint 担保済み項目（AI レビュー対象外）」節には**載せない**（`lint-scaffolding` SKILL Step 4-2）
- **理由・参照**: 採否の理由。生成ルールの場合は検証（違反 / 適合サンプルへの実実行）の事実も書く

## ミューテーションテスト設定の記録

事前ビルド設定は init がプロダクトの `lint/mutation/` に配置する（nextjs-react → `lint/mutation/stryker.config.mjs` + `stryker.diff.config.mjs` + `changed-ranges.mjs`、java-springboot → `lint/mutation/pitest.gradle`）。対象スタックに資産があれば**配線**し、なければ生成する（`lint-scaffolding` SKILL Step 3-3）。選択と担保手段を記録する。

- **担保手段**: 配線した場合は事前ビルド設定の参照（`lint/mutation/stryker.config.mjs` + `stryker.diff.config.mjs` + `changed-ranges.mjs` / `lint/mutation/pitest.gradle`）を、他行が `lint/...` 資産を参照するのと同じ形式で書く。生成した場合は生成物のパスを書く
- **選択**: `配線` / `生成` / `スキップ` のいずれか。配線・生成は全体 / 差分スコープのエントリポイント（JS: `mutation:full` / `mutation:diff`、Java: `mutationFull` / `mutationDiff`）の登録と**実実行によるミュータント生成・スコア算出の確認**まで済ませて初めて完了（Step 3-3 配線完了条件）

## 更新規律

- **ルールを追加・削除・不採用に変更するたびに本台帳を更新する。** 台帳と実配線（`lint:all` が実行する内容・レビューガイドの記載）を乖離させない
- **スタック変更時（FW・DB アクセス層の追加/変更、init 再実行による資産更新）は `lint-scaffolding` スキルを再実行し**、影響する行を見直す。決定済みで影響のない行は引き継ぐ
- **カテゴリ ID（A1〜F2）は安定識別子であり、再採番しない**（カタログ §1）。カタログにカテゴリが追加された場合は各グループの末尾行として追記し、廃止された場合も行を欠番として残して経緯を「理由・参照」に書く
- Lint 担保から AI レビュー担保へ切り替える（またはその逆の）変更は、レビューガイド（`.github/review-*.md`）の「Lint 担保済み項目（AI レビュー対象外）」節と `（Catalog: <番号>）` 付記も同時に更新する
