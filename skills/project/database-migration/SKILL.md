# Database Migration Skill - DBマイグレーション

導入先の補足ファイル `documents/development/project/database-migration.md` があれば、その段で読む。補足ファイルは製品への当てはめ（コマンド・パス・ポート等）だけを持ち、本スキルの規則を緩めない。食い違えば本スキルが優先する。

## 禁止事項（最重要）

> **以下は絶対に禁止。違反は許容されない。**

- **既存マイグレーションファイルの変更・削除禁止**: チェックサムエラーが発生する
- **mainブランチ確認なしでのファイル作成禁止**: バージョン番号が重複する

**バージョン番号の欠番は原則作らない**（連番で管理する）。並行ブランチの追い越しなど、やむを得ない導入先は、理由を補足ファイル（上記）に書いて個別に扱う。

## ファイル命名規則

プロジェクトのマイグレーションツール（Flyway, Prisma, Alembic 等）の命名規則に従う。

## バージョン番号決定手順（必須）

### Step 1: mainの最新状態を取得

```bash
git fetch origin main
```

（feature ブランチ上で `git pull origin main` を使わないこと — main がマージされて余分なマージコミットが生じ、quality-check や hook が使う `origin/main...HEAD` の差分基準がずれる。バージョン確認は `origin/main` の参照だけで足りる）

### Step 2: 最新バージョン番号を確認

プロジェクトのマイグレーションディレクトリを確認し、最新のバージョン番号を取得する。

### Step 3: マイグレーションファイル作成

次の連番でファイルを作成。

## SQL記述ルール

- `CREATE TABLE IF NOT EXISTS` を使用（冪等性の確保）
- インデックスは必要なカラムに適切に作成
- 外部キー制約を適切に設定
- デフォルト値を明示的に指定
